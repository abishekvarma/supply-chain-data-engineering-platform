# Contributing

Thank you for your interest in contributing to the Supply Chain Data Engineering Platform.

## Development Guidelines

- Follow the existing project structure.
- Write clean, readable, and maintainable code.
- Keep ingestion, transformation, quality, and utility logic separated.
- Add appropriate tests for new transformation logic.
- Update documentation when introducing new components.
- Never commit secrets, credentials, connection strings, or sensitive data.

## Pull Requests

Before submitting a pull request:

1. Validate the changes locally.
2. Run the relevant tests.
3. Review the code for unnecessary changes.
4. Update documentation if required.
5. Provide a clear pull request description.

## Commit Messages

Use clear and meaningful commit messages.

Examples:

- `feat: add shipment transformation`
- `fix: handle null delivery dates`
- `docs: update architecture documentation`
- `test: add shipment quality checks`

## Data .

Do not commit production data or confidential business information.

Use synthetic or anonymized datasets for development and demonstration.
